## Acceptance and evidence discipline

- Ticket 1 owns first-review runtime/usefulness/security negatives; Ticket 2 owns
  rework lineage, budget exhaustion and full crash matrix; Ticket 3 owns combined
  acceptance, predecessor compatibility and the final gate audit. Shared guards
  are tested when changed; unchanged expensive proof is reopened rather than rerun.
- Source/image/catalogue/checklist or boundary changes invalidate related evidence.
  README participates in canonical source identity. Never attach historical
  qualification to a new source digest, new grant or new reviewed bytes.
- Reopen current checks and approving independent review before reporting verified
  local output. Native done, model prose, attachment presence, old approval or a
  successful CI run alone is insufficient. Wrong/stale/unknown facts fail closed.
- Retain private bounded manifests, packets/verdicts, grants/run/process facts,
  command/result records, crash boundaries, cleanup and artifact hashes under
  ignored runtime storage; summarize sanitized facts here. Do not commit runtime
  state, private repository contents, provider tokens or real vault data.
- Future updates must identify exact tested commit or uncommitted source digest,
  image/native identity, actual passed/failed/skipped checks and evidence paths.
  Evidence summaries are local observations, not signed external attestation.
