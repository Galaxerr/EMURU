### MCP timeout investigation: independently captured evidence

Follow-up verification on 2026-10-12 at 14:02 UTC used the same checkout plus the
test preflight and documentation changes. The evidence below supplements the
acceptance results above; Docker/build and operator evidence were not rerun as
part of this test-only investigation.

Before any code change, this exact command failed twice in restricted execution
(33.31s and 33.38s, exit 1, `TimeoutError` at `session.initialize()`), then passed
with approved host execution (2.65s, exit 0):

```bash
UV_CACHE_DIR=/tmp/emuru-uv-cache uv run --frozen pytest -q tests/telegram/test_telegram_vault_integration.py --tb=short
```

The sandbox permits `socket.socketpair()` but denies `send()` with
`PermissionError: [Errno 1] Operation not permitted`. CPython 3.12's
`asyncio/selector_events.py::_write_to_self()` suppresses this `OSError` after a
debug log. AnyIO worker completion uses `loop.call_soon_threadsafe()`; MCP stdio
uses threaded file reads/writes. The denied wakeup prevents the event loop from
resuming that I/O. Changing `UV_CACHE_DIR` does not grant IPC permissions.

A temporary diagnostic outside the repository,
`.venv/bin/python /tmp/emuru-mcp-startup-probe.py`, copied the synthetic vault,
sent one JSON-RPC initialize request to the real MCP server, closed stdin, and
captured stderr and child exit. Restricted execution constructed the server in
1.021s, logged `Fail to write a null byte into the self-pipe socket` with `EPERM`,
and produced no response. The diagnostic terminated and reaped the child after
5.033s (exit -15). Approved host execution constructed the server in 1.123s,
returned response id 1, and exited normally on EOF (exit 0, total 1.507s).
This reproduces the failure without pytest, queue replay, or shared fixtures;
startup completed promptly in both environments.

The session-scoped `mcp_environment` fixture checks the required socketpair write
before the two stdio integration tests and async MCP tool tests. The runbook
documents approved host/CI execution. Production code, assertions, timeouts,
retries, skips, dependencies and lockfiles are unchanged.
