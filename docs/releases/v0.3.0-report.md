# EMURU v0.3.0 — completion report

Concluded: 2026-10-05
Branch: `feat/v0.3.0-hermes`
Comparison base: `main` (`8671978`)

## Outcome and scope

The v0.3.0 branch work is concluded with Hermes CLI integration of the existing
vault MCP, a conversational policy, explicit Gemini/OpenAI/Ollama model
selection, synthetic integration fixtures, and automated contract checks.
This report covers both committed branch changes and the implementation
present in the working tree at documentation time.

The initial progress document grouped Telegram reliability and lifecycle
management into later v0.3.0 phases. Those features were not delivered by this
branch and are deferred. Completion here refers to the delivered branch scope;
it does not assert that all originally proposed phases shipped, that a release
was tagged/merged, or that a real-vault deployment was accepted.

### Vault integration and agent policy

- Added synthetic fixtures under `tests/fixtures/hermes-vault`: an empty Inbox,
  the EMURU project, linked Hermes/MCP resources, and an untrusted reference
  containing instructions that must be treated as data. Source marker
  `PHASE2_PROJECT_SOURCE_742` supports retrieval acceptance checks.
- Added `infra/hermes/vault-binding.json` to bind the existing `emuru-index`
  and `emuru-vault-mcp` entry points, `EMURU_VAULT_PATH`, and tool arguments.
- Added `scripts/hermes-vault.py` modes `prepare`, `serve`, `inspect`, and
  `check`. The default is `.runtime/vault`; preparation preserves an existing
  runtime copy. Inspect/check use disposable fixture vaults. Backend startup
  uses frozen, offline, no-sync uv execution and a reduced environment.
- Added `infra/hermes/runtime-settings.json` for provider-independent vault
  policy and `scripts/hermes-vault-profile.py` for offline validation, live
  audit, and application. The script rejects unexpected MCP registrations,
  inline model credentials, expanded tool permissions, retries, and fallback.
- Restricted Hermes CLI exposure to the five vault tools, with 15-second MCP
  connection/tool timeouts; parallel calls, sampling, elicitation, resources,
  and prompts are disabled. Telegram tools remain disabled.
- Added `agents/emuru/SOUL.md` for evidence-based answers with path citations,
  relationship retrieval, language matching, prompt-injection handling,
  duplicate checks, and proactive Inbox memory for meaningful owner facts.
  It requires immediate failure reporting and prohibits retries or bypasses.
  Install this file separately in the Hermes profile; profile application
  does not deploy it.

The v0.2 indexer and MCP remain the authority for vault permissions. Writes
create new Inbox notes and reindex immediately; existing notes cannot be
updated or overwritten. The policy's conditional update guidance grants no
additional capability. Proactive memory and prompt-injection resistance are
policy instructions, not behavior established by the stdio contract test.

### Provider selection and Ollama support

- Added `infra/hermes/model-selection.json` to hold the explicit route without
  credentials; no automatic provider/model fallback is enabled.
- Added `src/emuru/providers.py` to validate and dispatch selections, with
  separate `gemini.py`, `openai.py`, and `ollama.py` provider modules.
- Gemini accepts `gemini-*` IDs through `chat_completions`; OpenAI accepts
  `gpt-*` IDs through `codex_responses`. Their routes restore provider settings
  and clear the Ollama context override when switching back.
- Ollama accepts loopback HTTP and the official direct HTTPS cloud endpoint.
  Local requests do not forward `OLLAMA_API_KEY`; direct cloud requests
  require it. Checks report connection, authentication, quota, missing-model,
  and tool-capability failures.
- Added daemon catalog discovery and model inspection, including custom names
  and cloud aliases identified through remote metadata. Downloaded models use
  a 65,536-token context setting and 180-second timeouts; cloud routes clear
  that setting and use 60-second timeouts.
- Added a synthetic chat/tool/result round-trip smoke test. Direct cloud
  preflight checks catalog membership; smoke establishes tool calling because
  its catalog does not advertise that capability.
- Added `scripts/hermes-ollama.py` for `--list`, interactive/exact `--select`,
  connection checks, `--smoke`, and temporary `--model` overrides. Selection
  uses all available daemon catalog models with no hardcoded menu or automatic
  model download, and can replace a saved Gemini/OpenAI route. Non-tool models
  may be selected but cannot pass vault-chat preflight.
