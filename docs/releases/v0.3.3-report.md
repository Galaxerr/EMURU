# EMURU v0.3.3 release report

Status: candidate under final review, not yet accepted. The 2026-10-09 rerun
passed the full project suite (245 passed, 3 skipped, 118 subtests), Ruff,
baseline, synthetic vault, offline profile/Telegram, native Telegram seams and
Compose validation. Actual pinned-proxy testing exposed truncated-stream
normalization; independent review also found CLI subprocess and late-worker
guard gaps. These are being corrected and invalidate earlier completion claims
below until the final integrated checks are recorded.

## Delivered

- Hermes CLI and guarded Telegram inference use the authenticated local LiteLLM
  alias only.
- LiteLLM performs one primary cloud attempt, then at most one qualified local
  attempt. Hermes retries, recovery, and fallback providers remain disabled.
- Local fallback requires a matching model digest, runtime, template, context
  contract, counting evidence, and unexpired qualification. Missing or stale
  evidence disables local dispatch.
- The gateway buffers streams, validates complete responses and tool arguments,
  rejects partial or unsafe results, enforces bounded deadlines, and stops after
  cancellation.
- Telegram preserves durable receipts, serialized execution, at-most-once
  notices, and conservative effect reporting.

## Acceptance gaps

This release does not claim live qualification or production acceptance:

- No production local model digest, runtime qualification, hardware benchmark,
  or populated-cache persistence was verified.
- No real-vault permission/write acceptance was performed.
- No owner Telegram delivery smoke was performed.
- Gemini/OpenAI account access was not tested.
- Docker and pinned Hermes checks require the owner environment.
- The full disposable checker needs a follow-up fix or rerun for its temporary
  Compose network/DNS seam before claiming container acceptance.

These gaps belong to owner-operated acceptance or v0.3.4 qualification.
