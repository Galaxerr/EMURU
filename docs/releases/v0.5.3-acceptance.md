Status: implementation complete; local automated acceptance recorded below.

No commit, push, merge, tag, live deployment or real-vault write is authorized
or performed by this implementation.

## Scope and decisions

- Feature branch: `feat/v0.5.3-isolated-scout`; existing `AGENTS.md` edits preserved.
- Package/lock version: 0.5.3; no dependency or native schema/pin upgrade.
- Opt-in `scout.compose.yaml`; default Compose services and wake behavior unchanged.
- Fixed first-party inspection interface, rather than general terminal/file tools.
  No model call, coding, test execution, install, remote publication or note update.
- Explicit local operator authorization through a private owner-owned policy:
  tracked task IDs, approved repository path/label, exact HEAD, selected files
  and a 1..120 second worker budget. Telegram text cannot select host paths.
- Numbered immutable snapshot blobs: committed regular UTF-8 files only; no
  `.git`, uncommitted files, symlinks, submodules, hooks or filters in the worker.
  Git transports are disabled during export. Limits: 100 files, 256 KiB/file,
  2 MiB total; reports at most 64 KiB.
- Unprivileged network-disabled worker with read-only root/snapshot, dropped
  capabilities, no new privileges, memory/CPU/PID limits and explicit signal
  deadlines. No board, vault, owner approval state, bot/provider credentials,
  host home or Docker socket is mounted.
- Separate trusted offline ledger container mounts only the existing board
  directory. Host owns Docker; worker never owns board claims or attachments.
- Native APIs create an independently identified `emuru-scout` reconnaissance
  card, unblock/claim it, attach a private content-addressed report and complete
  its exact run. Original coding task remains blocked. Schema-1 bodies retain
  project/spec/approval/task/grant bindings; no second queue or database.
- Trusted host independently computes expected metadata and verifies worker
  output. Receipt binds repository label/path-derived ID, baseline, report digest,
  native attachment and run. Status checks stored bytes and receipt/grant identity.
- Host dispatcher flock plus persisted native ownership permits one active
  attempt. Running/ready/blocked scouts prevent new grants until explicit operator
  reconciliation. Same grant, including an archived one, never automatically runs
  again. SIGTERM/failure blocks its exact run; abrupt death can remain uncertain.
- `/project status` reports reconnaissance separately, without claiming coding,
  tests, review or vault capture. M2 remains usable without a scout service.

Reports contain file paths, sizes, line counts, hashes, directory map and bounded
next steps. They contain no source text, semantic review or test results. Reports
and native attachments live under the existing private board directory and must
be retained with the complete stopped profile. Full lifecycle recovery belongs
to M6; model/coding qualification belongs to M4.
