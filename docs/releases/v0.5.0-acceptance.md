## Verified fixes

1. Inbox capture records authenticated request intent before publication and keeps
   its durable result independently of Telegram receipt pruning. Repetition returns
   the existing result; a lost acknowledgment remains uncertain and never recaptures.
2. One owner-turn deadline bounds model, operator and preview phases together.
   The 600-second turn and 660-second Compose shutdown budgets are unchanged.
3. Offline native diagnostics select temporary profile state before importing the
   native gateway. Regression and production file inventories verify isolation.
4. Qualification project/review output receives 2048 tokens within the existing
   4096-token reserve. Prompts specify JSON null, review JSON and exact source lines.
5. Qualification proposal schema now matches MCP: only `path` is required; omitted
   nullable fields use their declared defaults. Unknown fields, invalid types and
   string `"NULL"` remain invalid. Revision, exact-content and request identity checks
   remain mandatory. The original generic proposal exception is reproduced by
   replaying a captured native call through the old parser.
6. Local qualification uses native Ollama `/api/chat`, `think=false`, tool-result
   replay and the required 65,536-token context. Cloud uses its existing transport.
   Validators reject wrong-note injection reads, additional final tool calls,
   unrelated stale revisions, altered task lines and changed replay arguments.
7. Private failure evidence records stage/model, expected schema, actual synthetic
   response and underlying exception. Public reports exclude response bodies.
8. Disposable validation accepts `EMURU_TEST_IMAGE` so this candidate can be tested
   without replacing the production image tag. The default remains `emuru:latest`;
   regression covers both choices. No production interface or dependency was added.

## Model qualification and laptop safety

The audited full live run used an isolated route, synthetic vault and pinned Docker
Ollama 0.40.0 at temporary `http://127.0.0.1:11435`. Cloud `gemma4:31b` passed five
repetitions of every workflow (70 calls). Docker `qwen3.5:2b-q4_K_M`, manifest
`1e2d21a4f03ab9e4a9c1976a4b7e88f21de61d65f2c5485d8fde8942be73f1e7`,
passed retrieval/navigation/Inbox repetitions, then failed first project creation
(31 local calls). Expected an exact task line and null creation revision; actual
content prefixed the task with `*Task line:*` and invented a revision from the
filename. Independent stale/repeat probes returned an empty assistant response
without the required tool call. **The selected 2B model is unqualified.** Later
context, warm latency and hardware gates were not reached; no record was issued.
The cloud workflow result alone is not complete fallback qualification.

The original proposal-parser mismatch was an implementation defect; the remaining
argument/content failures are observed model limitations. `gemma4:e4b` also altered
project/anchor syntax and request identity in targeted probes; it is not a qualified
replacement. All acceptance thresholds remain unchanged.

For the requested `qwen3.5:9b` assessment, the Ryzen 5 5500U laptop has 14.96 GiB
physical RAM, approximately 9.25 GiB available at assessment, shared integrated
Radeon memory and no resident host model. Conservative planning used:

- Approximately 6.6 GB Q4_K_M weights from the
  [official Ollama model listing](https://ollama.com/library/qwen3.5:9b).
- 2 GiB full-attention KV estimate at 65,536 tokens:
  `65536 × 8 layers × 2 × 4 KV heads × 256 head dimension × 2 bytes`, using the
  [Qwen architecture configuration](https://huggingface.co/Qwen/Qwen3.5-9B/raw/main/config.json)
  and [Ollama's default f16 KV cache](https://docs.ollama.com/faq#how-can-i-set-the-quantization-type-for-the-k-v-cache).
- 1 GiB runtime allowance: approximately 9.15 GiB working set before uncertain
  recurrent state, graph, scratch and prefill buffers. A further 2 GiB desktop
  reserve requires approximately 11.15 GiB available.

This estimate leaves insufficient safe headroom now. **Zero 9B qualification
attempts; no weights downloaded or loaded. Capability is untested**, not failed.
Swap and shared GPU memory were not counted as additional physical RAM. No smaller
context, altered cache precision or relaxed criterion was tried. Local model
experiments stop here. A larger tool-capable model needs a host with adequate RAM
and complete unchanged qualification; neither 9B nor another replacement is certified.

The prior Docker run imported 1,945,781,358 bytes of already-cached 2B weights,
verified every blob, then stopped Docker Ollama and removed temporary publication.
