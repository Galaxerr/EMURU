`run_inference` reuses the existing final-frame protocol. It now requires exact
frame fields, a non-boolean integer tool count matching observed requests, a matching
immutable image/container identity and consistent daemon-observed exited state.

inspection or conflicting evidence is refused. Launch, inspect and cleanup use
the same filtered Docker environment. The receipt is returned only after removal
and independent absence checks succeed; removal errors cannot become success.
No new protocol, nonce, signing key, dependency or execution backend was introduced.
Authentication relies on trusted host/Docker and pinned native code, not on the
frame's SHA-256 alone. This attests native lifecycle, not candidate semantics.

### Precise remaining trust primitive

The missing primitive is an integrity-protected callable-return observer and
result serializer that arbitrary candidate Python cannot modify, impersonate or
invoke out of sequence. `candidate_main` currently shares an interpreter with
that code. Read-only files and execve confinement do not protect interpreter
frames/globals or prevent `ctypes` access to its memory and completion paths.

A parent wrapper protects its own memory but still receives the child's claim
that the function returned. Private descriptors, challenge replies, markers and
exit conventions remain reproducible by that child. Docker/`waitpid` attest exit;
trace/audit callbacks or designated completion syscalls remain candidate-reachable.
None provides the missing protected return observation. No such guarantee was
invented or replaced with a weaker interpretation of the approved contract.

binding and confirmed that it must not be presented as candidate completion.

artifact's hash, four calls, normal native exit/removal and false task outcome.

## Remaining limits

### Completion observer reassessment (2026-10-30)

Ticket 1 remains **BLOCKED**. A separate Python supervisor and candidate worker
would protect supervisor memory, but would not authenticate a callable return:
candidate Python can inspect its stack, discover inherited IPC, and write the
worker's purported return before exiting. Requiring normal worker exit, a nonce,
stdout, exit status or a candidate-generated frame does not close that channel.
No such partial design was installed.

The missing enforceable boundary is a trusted execution runtime that owns the
call boundary and return serialization while candidate instructions cannot read
or write its reporter state. The current unrestricted Python worker does not
provide that boundary. Until an isolated runtime with that property is selected
and independently reviewed, qualification must keep latching
`completion_unverified`. Existing Docker lifecycle evidence and successful
behavioral cases do not prove callable-return authentication. No live fixture,
full suite, local CI or security review was rerun for this reassessment.

The syscall guard supports Linux x86-64 only and refuses other platforms. Provider
usage is observational; there is no monetary cap guarantee. Supplemental test
counts remain unknown rather than copied from untrusted output. Successful fixed
cases do not prove universal correctness. Runtime turn/attempt limits and all
required invariants still need complete qualification after the blockers are fixed.
